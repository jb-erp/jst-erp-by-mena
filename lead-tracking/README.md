# Lead Tracking & Performance Log

เว็บแอปติดตาม Lead คลังสินค้าและโลจิสติกส์ในไทย ทำงานเป็น Artifact บน claude.ai

## ฟังก์ชัน
- แผนงานวันนี้: เป้าต่อวัน นัดตามต่อที่ถึงกำหนด และรายใหม่ที่ควรโทรก่อน
- คิวติดต่อ ต้องตามต่อ ทั้งหมด: รายชื่อพร้อมตัวกรอง เกรดความพร้อมติดต่อ และบันทึกสถานะ โน้ต วันนัด
- รายงานผล: ตัวเลขหลัก กิจกรรม 14 วัน และผลแยกตามกลุ่ม จังหวัด คำค้น
- หา Lead เพิ่ม: ค้นจาก Google Maps ด้วย Apify (compass/crawler-google-places) หาแบรนด์ออนไลน์ หาช่องทาง Facebook / Shopee / Lazada / TikTok เพิ่มเอง และประวัติการค้นหา
- ตั้งค่า Apify: สถานะการเชื่อมต่อ ลิงก์ Billing เพดานค่าใช้จ่ายต่อครั้ง และแถบเพดานการใช้งานรอบบิล
- ธีมขาว / มืด

## สองเวอร์ชัน
- **บน claude.ai** (`dist/index.html`): ข้อมูลแชร์กันทั้งทีมที่ได้รับแชร์ ใช้ Apify ผ่านการเชื่อมต่อในบัญชี Claude ของแต่ละคน
- **บน GitHub Pages** (`index.html`) เปิดที่ https://jb-erp.github.io/jst-erp-by-mena/lead-tracking/
  - แต่ละเครื่องใส่ Apify API token ของตัวเองที่เมนู ตั้งค่า Apify token เก็บในเบราว์เซอร์เครื่องนั้นเท่านั้น
  - นำเข้ารายชื่อจากไฟล์ `leads.json` ที่เมนู ตั้งค่า Apify หัวข้อ ข้อมูลในเครื่องนี้ ไฟล์รายชื่อไม่ได้อยู่ใน repository
  - สถานะ โน้ต และ Lead ที่เพิ่ม เก็บในเบราว์เซอร์เครื่องนั้น ไม่แชร์กับเครื่องอื่น ใช้ปุ่มดาวน์โหลดไฟล์สำรองและกู้ข้อมูลเพื่อย้ายเครื่อง

## โครงสร้าง
- `src/page.html` หน้าเว็บและ CSS
- `src/js/*.js` โค้ด แยกตามส่วน (รวมตามลำดับชื่อไฟล์)
- `src/standalone.js` ส่วนที่ทำให้เวอร์ชัน GitHub Pages ทำงานเองได้ (ที่เก็บข้อมูลในเบราว์เซอร์ และเรียก Apify API ตรง)
- `src/build.py` สร้างทั้งสองเวอร์ชัน สั่งด้วย `python3 src/build.py` ในโฟลเดอร์ `lead-tracking`

## ข้อจำกัด
- ไฟล์รายชื่อ `leads.json` มีชื่อร้าน เบอร์โทร และที่อยู่ จึงไม่ได้เก็บไว้ใน repository นี้
- `dist/index.html` ทำงานได้เฉพาะบน claude.ai เวอร์ชัน GitHub Pages คือ `index.html`
- อย่าใส่ Apify token ในเครื่องที่ใช้ร่วมกับคนอื่น และตั้งวงเงินรายเดือนในบัญชี Apify ไว้
